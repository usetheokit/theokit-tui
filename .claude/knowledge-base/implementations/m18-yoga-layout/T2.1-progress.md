## GREEN

- `src/renderer/text-measure.ts` — Ink's measure-text / wrap-text /
  squash-text-nodes / dom.js:measureTextNode ported over the SAME libs Ink uses
  (`widest-line`, `wrap-ansi`, `cli-truncate`, `string-width`): `measureText`
  (widest line × height), `wrapText` (wrap / hard / truncate-end/start/middle),
  `squashTextNodes` (concat children applying each SGR `internal_transform`), and
  `measureTextNode` (the yoga measure func: fit → intrinsic, `<1px` guard, else
  wrap+re-measure).
- `src/renderer/output-grid.ts` — Ink's `output.js` cell grid ported, **minus
  clips** (no shipped component uses overflow — YAGNI). A height×width styled-cell
  buffer that preserves trailing padding rows (a naive line-walk cannot), places
  wide (CJK) chars across two cells with overwrite cleanup, applies per-line
  transformers, and collapses to `\n`-joined rows via `@alcalzone/ansi-tokenize`
  + `trimEnd()`.
- `host-config.ts` — `createInstance` now binds `measureTextNode` to each
  non-virtual `ink-text` yoga node (`setMeasureFunc`), so `calculateLayout` sizes
  text. Verified by a layout test: `<Box><Text>hello</Text></Box>` computes the
  text to width 5, height 1.

## Scoped divergence (documented, not silent)

`sanitizeAnsi` is a pass-through for M18: our corpus text is SGR-only (chalk
transforms) and never carries raw cursor/clear control sequences, so Ink's fuller
sanitize (which would require porting its private `ansi-tokenizer`) is a provable
no-op on our inputs. Recorded here + in the M18 parity report; no shipped
component injects control codes into `<Text>`.
