## GREEN

- `src/renderer/input/input-parser.ts` — the byte framer, a faithful port of Ink's
  `input-parser.js` (MIT): slices a raw stdin stream into complete key/paste events;
  CSI (`\x1b[…final`) / SS3 (`\x1bO<final>`) / ESC-alt / escaped-codepoint framing;
  `pending` accumulation across chunks; bracketed-paste (`\x1b[200~`…`\x1b[201~`)
  framed as an atomic `{paste}` (markers stripped); held-backspace runs split into
  individual events; `hasPendingEscape`/`flushPendingEscape` for the lone-ESC debounce.
- `src/renderer/input/parse-keypress.ts` — the keypress semantics, a faithful port of
  Ink's `parse-keypress.js` LEGACY path (kitty CSI-u decode deferred to M21): a framed
  sequence → `{name, ctrl, meta, shift, sequence}`. Table-driven control-char match +
  single-char match + escape-form (metaKeyCode / CSI-SS3 fn-key with modifier bits +
  rxvt ctrl/shift codes). The Ctrl+J-newline contract (`\n` → name "enter", all flags
  false) preserved. ESC injected via `String.fromCharCode(27)` so no control char is a
  regex literal (eslint no-control-regex).
- `src/renderer/input/key.ts` — `projectKey(sequence)` → `{ input, key }`, the exact
  12-field `Key` the composer consumes (Ink's use-input.js:40-100 projection): special
  keys blank the printable `input`; ctrl+letter input is the letter; uppercase sets shift.
