# @theokit/tui — Roadmap

> Macro roadmap generated by `/roadmap-init` on 2026-07-05. Milestones M0–M8, checkbox per milestone.
> Flip `[ ]` → `[x]` in each header as work lands (via `cycle-release` post-merge, or by hand).

## Vision

`@theokit/tui` is the **terminal-native sibling of `@theokit/ui`** — a TUI component library for
AI-agent surfaces (coding agents + chat), built on **Ink** (React for the terminal). It mirrors
`@theokit/ui`'s AI primitives (`AgentEvent`, `ToolCall`, `ChatMessage`, `DiffViewer`,
`TokenUsageChart`, …) as terminal components, so coding agents that run in the terminal get the same
coherent primitive set — same AI-native identity, terminal surface. Apache-2.0 community auxiliary of
the Theo ecosystem (the UI pillar's terminal counterpart).

## Problem

Coding agents increasingly run in the terminal (Claude Code, Codex CLI, Gemini CLI, opencode), but
each **rebuilds the same agent-UI TUI primitives from scratch** — streaming chat render, tool-call
cards with status, diff viewer, agent timeline, token/cost meter, input composer. No reusable,
coherent TUI component library exists for AI-agent surfaces (the terminal analog of `@theokit/ui`).
It hurts **developers building coding agents / agent CLIs in TypeScript** (including our own
TheoCode), who spend weeks reimplementing streaming/tool-call/diff render in Ink before shipping
value.

## Users

- **Primary (external):** TypeScript developers building coding agents / agent CLIs on Ink.
- **First-party dogfood (internal):** TheoCode ("desktop + CLI assistant") — the anchor consumer.
- **Posture:** Apache-2.0 community auxiliary, not part of the paid funnel; usable standalone in any
  Ink app; pairs naturally with `@theokit/sdk` (harness) as the event source. Not for end-users or
  non-devs — for whoever builds an agent's terminal surface.

## Scope

### In scope (V1 — required to call this project alive)

- The **core agent-surface primitives** in Ink: chat (`ChatMessage`/`ChatThread`/`ChatComposer` +
  token-by-token streaming), tool-use (`ToolCall`/`ToolCallCard`/`ToolResult`), agent
  (`AgentEvent`/`AgentTimeline`/`AgentStreaming`), code (`DiffViewer`/`CodeBlock`), metrics
  (`TokenUsageChart`/`CostMeter`/`ContextWindowBar`).
- **Foundation:** theme system (terminal-adaptive, NO_COLOR/truecolor aware), tokens,
  `<TheoTUIProvider>`, and the **stream adapter** (`@theokit/sdk` events / `AsyncIterable` → UI
  state, mirroring theo-ui's `useAgentStream`).
- **Quality:** `ink-testing-library` snapshot tests, ESM-only, Apache-2.0, TS strict, mirrored
  quality gates.

### Explicitly out of scope

- **Generic TUI components** (menus, tables, forms, generic spinners, layout widgets) — that's
  ink-ui/@inquirer territory. We are AI-native, not a general-purpose TUI lib (Rule 9: don't reinvent).
- **A homegrown TUI framework** — we use Ink; no ratatui (Rust) or opentui port.
- **The agent harness/runtime** — `@theokit/tui` only renders; agent/LLM logic is `@theokit/sdk`'s.
- **A full coding-agent app/CLI** — that's TheoCode (consumer), not the lib.
- **Heavy view-only engines** from `@theokit/ui` (slide/whiteboard/diagram) — meaningless in a terminal.
- **1:1 web↔terminal parity** — only the agent-surface subset that makes sense in TUI.
- **shadcn registry / copy-paste** — TUI ships via npm only.

## Constraints

| Category | Constraint |
|---|---|
| Stack | TypeScript strict + Ink 5 (React 18/19 for terminal) + tsup (ESM-only) + vitest + `ink-testing-library`. React is the ONLY required peer; Ink as a dependency. |
| Compliance / legal | Apache-2.0; only compatible deps (no GPL/AGPL transitive). Prior art `assistant-ui/react-ink` is MIT — compatible for study, don't copy code without checking. |
| Deadline | None (solo/assisted). Each milestone runs the ecosystem cycles (discover → plan → implement → review → release). |
| Team | Solo + Claude (assisted). |
| Runtime target | Node ≥ 20, ESM-only (no CJS). Terminals: truecolor AND degrade to 16-color/NO_COLOR; variable width (resize); no mouse dependency; don't break on pipe/non-TTY (degraded render). |
| Budget (infra, tooling) | None beyond npm publish + a real-LLM key (OpenRouter) for the streaming demo. |

## Success criteria

**V1 ships (measurable):** TheoCode (dogfood) renders a full agent turn end-to-end in the terminal
using ONLY `@theokit/tui` primitives, with:

1. **≥ 12 agent-surface primitives** published (ChatMessage, ChatThread, ChatComposer, AgentEvent,
   AgentTimeline, ToolCall, ToolCallCard, ToolResult, DiffViewer, CodeBlock, TokenUsageChart,
   ContextWindowBar) + `<TheoTUIProvider>` + stream adapter.
2. **Real streaming demo** (`examples/live-agent-tui`) consumes an `AsyncIterable` of `@theokit/sdk`
   events against a real LLM (OpenRouter), rendering token-by-token text + live tool-cards.
3. **Green gates:** format → lint → typecheck → test → build exit 0; snapshot coverage ≥ 80% of
   primitives; ESM-only + Apache-2.0 + publint clean.
4. **Published:** `@theokit/tui` installable from npm; AI-native README.
5. **Robustness:** primitives degrade correctly in NO_COLOR and non-TTY (snapshot test both modes).

**North-star metric:** **Time-to-first-agent-turn-in-terminal (TTFATT)** — dev-minutes from
`npm i @theokit/tui` to a streaming + tool-calls agent turn rendered in the terminal. V1 target:
**< 10 minutes**. Secondary "winning" signal: adoption (projects/CLIs beyond TheoCode depending on
`@theokit/tui`; primitives reused per consumer).

## Milestones

### M0 — [x] Walking skeleton

**Objective:** Prove the whole toolchain end-to-end with the thinnest vertical slice: one primitive
rendering in a terminal, built + tested + snapshot-covered.
**Definition of done:**
- [ ] Repo scaffolded: Ink 5 + tsup (ESM-only) + vitest + `ink-testing-library` + TS strict +
  Apache-2.0 LICENSE/NOTICE; `pnpm build` produces `dist/index.js`.
- [ ] One primitive — `ChatMessage` (user/assistant) — renders in Ink; a `<TheoTUIProvider>` stub wraps it.
- [ ] `ink-testing-library` snapshot test asserts the rendered terminal output; `pnpm test` green.
- [ ] `format → lint → typecheck → test → build` all exit 0 in CI.
**Depends on:** — (project inception)
**Risks:** 1. Ink 5 + React 19 + ESM interop quirks in the build. 2. Snapshot flakiness from ANSI/width.

### M1 — [x] Chat surface core

**Objective:** Ship the chat primitives with token-by-token streaming render.
**Definition of done:**
- [ ] `ChatMessage` (user/assistant/system roles), `ChatThread` (scroll/viewport, `<Static>` for
  history), `ChatComposer` (multi-line input via `useInput`).
- [ ] Streaming: a message renders incrementally as tokens arrive (append-in-place).
- [ ] Snapshot tests for each role + a streaming sequence; a11y-ish: readable in NO_COLOR.
**Depends on:** M0
**Risks:** 1. Viewport/scroll correctness with variable terminal height. 2. Streaming re-render perf/flicker.

### M2 — [x] Tool-use surface

**Objective:** Ship tool-call primitives with the status lifecycle.
**Definition of done:**
- [ ] `ToolCall` / `ToolCallCard` with status lifecycle (running → success/failed), `ToolResult`
  (collapsed/expanded output; shell-envelope `{stdout,stderr,exitCode}` aware).
- [ ] Spinner/indeterminate state while `running` (via `ink-spinner`).
- [ ] Snapshot tests across all statuses + long/truncated output.
**Depends on:** M1
**Risks:** 1. Long tool output overflowing the viewport. 2. Status transitions racing the stream.

### M3 — [x] Agent surface

**Objective:** Ship agent-lifecycle primitives.
**Definition of done:**
- [ ] `AgentEvent` (thinking/action), `AgentTimeline` (ordered event log), `AgentStreaming` (live
  in-progress indicator).
- [ ] Composes with M1/M2 primitives (a timeline mixes messages + tool-calls).
- [ ] Snapshot tests for a representative multi-event turn.
**Depends on:** M2
**Risks:** 1. Timeline layout with heterogeneous item heights. 2. Event ordering under concurrency.

### M4 — [x] Code surface

**Objective:** Ship code-rendering primitives adapted to the terminal.
**Definition of done:**
- [ ] `DiffViewer` (terminal unified/split, +/- coloring, degrades in NO_COLOR), `CodeBlock` with
  syntax highlight (opt-in dep: `cli-highlight`/shiki-cli).
- [ ] Handles wide lines (wrap/truncate) + large diffs (windowing).
- [ ] Snapshot tests: added/removed/context lines; highlight on/off.
**Depends on:** M1
**Risks:** 1. Syntax-highlight dep weight / ESM interop. 2. Diff layout at narrow widths.

### M5 — [x] Metrics surface

**Objective:** Ship metric primitives as ASCII/terminal visualizations.
**Definition of done:**
- [ ] `TokenUsageChart` (ASCII bars), `CostMeter`, `ContextWindowBar` (fill gauge).
- [ ] Numbers formatted (k/M), degrade in NO_COLOR, adapt to width.
- [ ] Snapshot tests for empty/partial/full + narrow width.
**Depends on:** M0
**Risks:** 1. Meaningful ASCII charts at small widths. 2. Overclaiming precision in a text gauge.

### M6 — [x] Theme + robustness foundation

**Objective:** Finalize the theme system and terminal-robustness contract across all primitives.
**Definition of done:**
- [ ] Theme system (tokens + terminal-adaptive palette), `<TheoTUIProvider>` finalized, a
  `<ThemeProvider>`-equivalent + ≥ 2 built-in themes.
- [ ] Every primitive respects `NO_COLOR`/`FORCE_COLOR`/`TERM=dumb` and renders (degraded) in
  non-TTY/pipe.
- [ ] Snapshot matrix: each primitive × {truecolor, 16-color/NO_COLOR, non-TTY}.
**Depends on:** M1, M2, M3, M4, M5
**Risks:** 1. Combinatorial snapshot surface. 2. Terminal capability detection edge cases.

### M7 — [x] Stream adapter + Harness bridge

**Objective:** Ship the `@theokit/sdk` stream adapter that drives the primitives (the `useAgentStream` analog).
**Definition of done:**
- [ ] A hook/reducer maps an `AsyncIterable` of `@theokit/sdk` events (`text_delta`, `tool_call`
  lifecycle, `assistant`) → UI state driving `ChatThread`/`ToolCallCard`/`AgentTimeline`.
- [ ] Pure, exhaustively-tested reducer (mirrors theo-ui's `agentStreamReducer`); ZERO runtime
  coupling to `@theokit/sdk` (structural input type; sdk a devDependency for the demo only).
- [ ] Reconnect/resume across a dropped stream (opaque `lastEventId`) covered by a test.
**Depends on:** M3
**Risks:** 1. Structural-type drift vs the real SDK output. 2. Reducer complexity/correctness.

### M8 — [x] GA: dogfood + publish

**Objective:** Prove V1 end-to-end and publish `@theokit/tui` to npm.
**Definition of done:**
- [ ] `examples/live-agent-tui` renders a full agent turn (streaming + tool-cards) vs a real LLM
  (OpenRouter) using ONLY `@theokit/tui` primitives; TheoCode consumes the primitives (dogfood).
- [ ] ≥ 12 primitives published; snapshot coverage ≥ 80%; all gates green; publint clean.
- [ ] `@theokit/tui` published to npm; AI-native README; TTFATT measured (< 10 min target) + recorded.
**Depends on:** M6, M7
**Risks:** 1. "Published but no consumer" — mitigated by the TheoCode dogfood gate. 2. Real-LLM demo flakiness.

**Dependencies:** M6

> Skill-default: most recent `[x]` milestone at amendment time. User may have overridden to a different/wider set in grill Q2.

**Top risks (new — pre-existing risks documented elsewhere in roadmap):**

- Objectives/DoD are revised only between milestones (never mid-flight) — per `cycle-roadmap`.
- Adding a milestone later: `/roadmap-feature` (appends M9+ without renumbering).
